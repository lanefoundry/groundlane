# Groundlane browser infrastructure competitors

Research date: 2026-08-20. Sources are official product/docs pages fetched with `stealth_fetch` only.

## Executive read

The closest direct competitors are Browserbase, Browserless, Steel, and Hyperbrowser, but they sell broader platforms than Groundlane's MVP: cloud sessions plus proxies/CAPTCHA, persistent identity, debugging, agent integrations, and often one-shot scrape/crawl APIs.

- **Browserbase** is the strongest managed, enterprise-oriented benchmark: cloud browsers plus Fetch/Search/Agents/Runtime, hosted MCP, and a differentiated `Verified` identity product.
- **Browserless** has the broadest deployment story: managed cloud, hosted MCP, local MCP package, dedicated/private fleets, and licensed self-hosting. It is the clearest benchmark if Groundlane wants “same API anywhere.”
- **Steel** is the closest open-source/devtool benchmark: managed sessions plus a self-hostable local edition, explicit session APIs, scrape/screenshot/PDF tools, agent traces, and unusually transparent metered pricing.
- **Hyperbrowser** is the strongest breadth benchmark for an agent platform: sessions, Fetch/Search/Crawl, multiple built-in computer-use agents, HyperAgent, MCP, and agent sandboxes.

The viable wedge is therefore not merely “stealth fetch.” A sharper position is: **a vendor-neutral web access layer with safe-by-default URL handling, predictable bounded outputs, provider routing, and an internal browser fallback**. Competing head-on on CAPTCHA solving, residential proxy inventory, or fingerprint R&D would put the project against mature infrastructure vendors.

## What to copy, and what not to copy

### High-value parity

1. **Separate surfaces:** one-shot `web_fetch` for cheap bounded retrieval; explicit session tools, if later added, must remain a distinct stateful capability. Browserbase, Browserless, Steel, and Hyperbrowser all separate these use cases in some form.
2. **Hosted Streamable HTTP MCP:** Browserbase and Browserless make remote MCP the lowest-friction path; this directly solves Claude Code cloud availability.
3. **Explicit session handles:** Steel's MCP recipe is the cleanest model for multi-client isolation and billing-safe cleanup.
4. **Observability:** return status, final URL, challenge state, timings, truncation, screenshots, and later session replay/live view. Competitors treat debugging as a product feature, not an implementation detail.
5. **Deployment portability:** Browserless and Steel show the value of a stable API across managed and self-hosted environments.

### Avoid promising early

- Do not claim universal “stealth” or anti-bot bypass. Mature vendors qualify success and combine browser fingerprints, proxies, CAPTCHA services, and site-specific infrastructure.
- Do not bundle a residential proxy network initially. Support BYOP first; add a managed provider only when demand and abuse controls justify it.
- Do not imitate broad agent frameworks yet. The defensible early advantage is a reliable, auditable transport and execution layer that works from local and cloud Claude/Codex.

## Naming implication

`Groundlane` remains credible because it describes infrastructure rather than promising bypass. If the product stays one-shot retrieval only, `PageProbe` or `RenderFetch` is more precise. If it adopts stateful sessions and remote MCP, `Groundlane` best matches the competitive category.
